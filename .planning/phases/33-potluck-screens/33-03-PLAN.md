<objective>
Fix the "Add New Category" button so it creates a local-first optimistic category card instead of immediately calling the API with an empty name (which returns 400 "name is required").

Purpose: UAT revealed that tapping "+ Add New Category" immediately shows an error toast because handleAddCategory calls createPotluckCategory with name:"" which the backend correctly rejects. The fix is to add the category to local state first and only persist on name blur.

Output: Updated potluck-setup.tsx with local-first optimistic creation pattern.
</objective>

1. **Widen the category ID type to support temp IDs.** The TPotluckCategory type uses `id: number`, but temp entries need string IDs. Add a local type alias at the top of the file:
```ts
type LocalCategory = Omit<TPotluckCategory, 'id'> & { id: number | string };
```
Update the `categories` state type from `TPotluckCategory[]` to `LocalCategory[]`. Update `handleCategoryUpdate` and `handleCategoryDelete` parameter types accordingly.

2. **Update CategoryCard props** to accept `LocalCategory` instead of `TPotluckCategory` for the `cat` prop. The `onDelete` callback should accept `number | string` instead of just `number`.

3. **Replace handleAddCategory (lines 489-503).** Remove the API call entirely. Instead:
```ts
const handleAddCategory = useCallback(() => {
  const tempId = `temp-${Date.now()}`;
  const tempCat: LocalCategory = {
    id: tempId,
    eventId: parseInt(id, 10),
    name: '',
    quantity: 1,
    foodImageUrl: null,
    suggestionChips: [],
    status: 'draft',
    sortOrder: categories.length,
    createdAt: new Date().toISOString(),
    updatedAt: new Date().toISOString(),
  };
  setCategories((prev) => [...prev, tempCat]);
  setTimeout(() => {
    scrollRef.current?.scrollToEnd({ animated: true });
  }, 100);
}, [id, categories.length]);
```
Note: this is now synchronous (no async), no API call, no try/catch.

4. **Update CategoryCard's handleNameBlur (line 166-168)** to handle temp vs persisted categories differently. Replace the existing `handleNameBlur` with:
```ts
const isTemp = typeof cat.id === 'string' && String(cat.id).startsWith('temp-');

const handleNameBlur = async () => {
  if (isTemp) {
    // Temp category: create on server if name is non-empty, discard if empty
    if (!name.trim()) {
      onDelete(cat.id);
      return;
    }
    try {
      const created = await modulesApi.createPotluckCategory(eventId, {
        name: name.trim(),
        quantity,
        foodImageUrl: foodImageUrl ?? undefined,
        suggestionChips: chips,
      });
      onUpdate({ ...created, id: created.id } as any);
      // We need a way to replace the temp entry — use a special callback
    } catch {
      showToast('Failed to save category. Please try again.');
    }
  } else {
    // Existing category: update as before
    saveCategory({ name, quantity, foodImageUrl, suggestionChips: chips });
  }
};
```

However, `onUpdate` matches by `cat.id` which is the temp ID, but the server returns a real numeric ID. To handle this replacement, add an `onReplace` callback prop to CategoryCard:
- Add `onReplace: (tempId: number | string, serverCat: TPotluckCategory) => void` to CategoryCardProps
- In PotluckSetupScreen, define:
```ts
const handleCategoryReplace = useCallback((tempId: number | string, serverCat: TPotluckCategory) => {
  setCategories((prev) => prev.map((c) => (c.id === tempId ? serverCat : c)));
}, []);
```
- Pass `onReplace={handleCategoryReplace}` to each CategoryCard
- In handleNameBlur for temp categories, call `onReplace(cat.id, created)` instead of `onUpdate`

5. **Guard saveCategory against temp IDs.** In `CategoryCard.saveCategory` (lines 143-164), the `modulesApi.updatePotluckCategory` call uses `cat.id` which would be a string for temp entries. Add an early return guard:
```ts
const saveCategory = useCallback(async (patch) => {
  if (typeof cat.id === 'string' && String(cat.id).startsWith('temp-')) return; // temp — not yet persisted
  try { ... }
}, [...]);
```
This prevents quantity/chip/image changes on temp cards from hitting the update API before the category is created.

6. **Guard handleDelete against temp IDs.** In `CategoryCard.handleDelete` (lines 228-237), if the category has a temp ID, just call `onDelete(cat.id)` without calling `modulesApi.deletePotluckCategory`:
