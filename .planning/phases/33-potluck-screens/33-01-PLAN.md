- `updatePotluckCategory(eventId: string, catId: number, data: Partial<{ name: string; quantity: number; foodImageUrl: string | null; suggestionChips: string[]; status: string; sortOrder: number }>): Promise<TPotluckCategory>` — PUT `/api/events/${eventId}/potluck/categories/${catId}`

- `getPotluckSignups(eventId: string): Promise<TPotluckSignup[]>` — GET `/api/events/${eventId}/potluck/signups`
- `createPotluckSignup(eventId: string, data: { categoryId: number; participantName: string; note?: string }): Promise<TPotluckSignup>` — POST `/api/events/${eventId}/potluck/signups`

Follow the exact same pattern as existing methods (apiClient.get/post/put/delete, return response.data).

Match the Potluck-Setup.png template. The screen must:

1. **AppHeader**: title "Setup Potluck", back button via `router.back()`, right action "Preview" text button that navigates to `/potluck?id=${id}` (preview mode).

2. **Plan-tier gate**: Read event from EventsContext by id (from `useLocalSearchParams`). If `event.planTier === 'free'`, show an upgrade prompt (copy the pattern from modules-config.tsx upgrade modal — centered icon, "Premium Feature" heading, description text, and a disabled "Upgrade Plan" button). Return early, do not render setup form.

3. **State management**:
   - `categories: TPotluckCategory[]` — loaded on mount via `modulesApi.getPotluckCategories(id)`
   - `loading: boolean` for initial load
   - `saving: boolean` for publish action

4. **Category cards** (ScrollView, one card per category):
   Each card has:
   - Category name input (TextInput, placeholder "Category name", e.g. "Main Dish")
   - "Quantity needed" label + stepper (minus/plus buttons around a number, min 1, max 50)
   - Food image: tappable Image or placeholder. Use `ImagePicker.launchImageLibraryAsync` with `quality: 0.5, aspect: [4, 3], allowsEditing: true, base64: true`. Store the base64 data URI in `foodImageUrl`. Read the image file with `FileSystem.readAsStringAsync(uri, { encoding: 'base64' })` pattern from edit-event-details.tsx if needed for the upload.
   - Suggestion chips: show existing chips as teal pill badges with X to remove. TextInput below for adding new chip (submit on Enter/blur if non-empty).
   - Delete category button (trash icon, top-right of card). Calls `modulesApi.deletePotluckCategory(id, cat.id)` then removes from local state.

5. **Auto-save on blur**: When a category name input blurs or quantity changes, call `modulesApi.updatePotluckCategory(id, cat.id, { name, quantity, foodImageUrl, suggestionChips })`. Do NOT debounce — just fire on blur/change. Show no save button per card.

6. **"+ Add New Category" button**: Calls `modulesApi.createPotluckCategory(id, { name: '', quantity: 1 })` and appends result to local state. Scroll to bottom after adding.

7. **"Save and Publish" button** (teal, bottom of scroll, full-width):
   - Must load current active modules FIRST via `modulesApi.getModules(id)`, then merge potluck into the set with status 'active' before calling `modulesApi.setModules(id, mergedModules)`. This prevents wiping other active modules.
   - Also update each category status to 'active' via `modulesApi.updatePotluckCategory(id, cat.id, { status: 'active' })`.
   - After publish, show success toast and navigate back.
   - If already published (all categories have status 'active'), change button text to "Update & Save".

8. **Empty state**: If no categories exist, show a friendly message like "No categories yet. Tap below to add your first potluck category!" with the Add button.

**Styling**: Use GlueStack UI components (Text, Pressable, Input, InputField, Image). Teal accent (#0d9488). Card backgrounds white with rounded-xl and shadow-sm. Same spacing patterns as edit-wishlist-item.tsx.
