    **Modify apps/gatherly-mobile/app/(tabs)/index.tsx:**

    Add an onboarding redirect check at the top of the component (after hooks):

    ```tsx
    import { useSession } from '../contexts/AuthContext';
    import { useRouter } from 'expo-router';

    // Inside the component, after existing hooks:
    const { user } = useSession();
    const router = useRouter();

    useEffect(() => {
      // Redirect to onboarding if user hasn't completed it
      // Skip for magic-link participants (they have participantId, not userId)
      if (user && !user.participantId && user.onboardingComplete === false) {
        router.replace('/onboarding/profile-setup');
      }
    }, [user?.onboardingComplete]);
    ```

    This is the standard Expo Router pattern for post-auth redirects: the authenticated user lands in (tabs), which checks `user.onboardingComplete` and redirects if false. After onboarding completes and `updateUser({ onboardingComplete: true })` is called, the `user` object updates, the effect re-runs, and the condition is no longer met — so the user stays in (tabs).

    **IMPORTANT:** Use `user.onboardingComplete === false` (strict equality), NOT `!user.onboardingComplete`. This prevents redirecting when `onboardingComplete` is `undefined` (which happens for magic-link participants whose User object doesn't have this field).
