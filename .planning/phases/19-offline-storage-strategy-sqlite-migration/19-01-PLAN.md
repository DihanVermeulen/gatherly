  <action>
1. Install expo-sqlite:
   ```
   cd apps/gatherly-mobile && npx expo install expo-sqlite
   ```
   expo-sqlite is part of Expo SDK 54, so `npx expo install` ensures the correct version.

2. Create `apps/gatherly-mobile/lib/database.ts`:
   - Export an `initDatabase()` async function that:
     - Opens database named `gatherly.db` using `SQLite.openDatabaseAsync('gatherly.db')`
     - Runs `PRAGMA journal_mode = WAL;` for crash resilience
     - Creates tables with `CREATE TABLE IF NOT EXISTS`:
       - `events` (id TEXT PRIMARY KEY, name TEXT NOT NULL, date TEXT, participant_count INTEGER DEFAULT 0, gift_count INTEGER DEFAULT 0, data TEXT NOT NULL, cached_at INTEGER NOT NULL)
       - `wishlist_items` (id TEXT PRIMARY KEY, name TEXT NOT NULL, description TEXT, url TEXT, data TEXT NOT NULL, cached_at INTEGER NOT NULL) — NOTE: Do NOT store image_url/base64 in SQLite to avoid bloat. Images will be re-fetched on demand.
       - `cache_meta` (key TEXT PRIMARY KEY, value TEXT, updated_at INTEGER NOT NULL)
   - Use a module-level singleton pattern: `let db: SQLiteDatabase | null = null;` so repeated calls return same instance
   - Export the `SQLiteDatabase` type from expo-sqlite for consumers

3. Create `apps/gatherly-mobile/lib/cache.ts`:
   - Import `SQLiteDatabase` from expo-sqlite
   - Export `cacheEvents(db, events: TEvent[])`: wraps in `db.withTransactionAsync`, does INSERT OR REPLACE for each event (id, name, date, participant_count from participants.length, gift_count from giftCount, JSON.stringify(event) as data, Date.now() as cached_at). Also delete events from cache that are no longer in the array (DELETE WHERE id NOT IN (...)).
   - Export `loadCachedEvents(db)`: SELECT data FROM events ORDER BY cached_at DESC, parse JSON, return TEvent[].
   - Export `cacheWishlistItems(db, eventId: string, items: TWishlistItem[])`: INSERT OR REPLACE each item (use `${eventId}_${item.id}` as composite key since wishlists are per-event). Strip image_url from the data blob before caching.
   - Export `loadCachedWishlistItems(db, eventId: string)`: SELECT data FROM wishlist_items WHERE id LIKE '${eventId}_%', parse JSON, return TWishlistItem[].
   - Export `clearCache(db)`: DELETE FROM events; DELETE FROM wishlist_items; DELETE FROM cache_meta; (used on logout)
   - Use the TEvent and TWishlistItem types from `@/app/api/events`

4. Create `apps/gatherly-mobile/lib/secureStorage.ts`:
   - Import * as SecureStore from 'expo-secure-store'
   - Define key constants: AUTH_TOKEN_KEY = 'gatherly_access_token', USER_KEY = 'gatherly_user', PUSH_TOKEN_KEY = 'push_token', PENDING_INVITE_KEY = 'pendingInviteToken'
   - Export `SecureStorage` object with typed methods:
     - getAuthToken / setAuthToken / removeAuthToken
     - getUser / setUser / removeUser (JSON serialize/deserialize)
     - getPushToken / setPushToken / removePushToken
     - getPendingInvite / setPendingInvite / removePendingInvite
   - NOTE: The key names MUST match what AuthContext.tsx already uses ('gatherly_access_token', 'gatherly_user') so existing sessions are preserved. Check AuthContext.tsx for exact key strings.

     - Uses useEffect to call `initDatabase()` on mount, sets db when ready
     - While db is null, render a minimal loading view (just a View with ActivityIndicator — import from react-native). Do NOT render children until db is ready, so downstream consumers can safely use useDatabase().

   - `useDatabase()` hook:
     - Gets db from context
     - Throws if null (should never happen since Provider blocks rendering until ready)
     - Returns typed `SQLiteDatabase`

   - Wrap the app content: DatabaseProvider should go INSIDE SessionProvider but OUTSIDE RootLayoutNav. The reason: DatabaseProvider is independent of auth, but downstream consumers (EventsProvider inside RootLayoutNav) will need both auth and db context.

   - Do NOT change anything else in _layout.tsx. The EventsProvider wiring happens in Plan 02.
