<objective>
Revert the 19-04 approach (EventsProvider inside Stack.Protected) which broke Expo Router navigation, and replace it with a key-based remount strategy: EventsProvider stays in its original position (outside Stack.Protected) but receives key={session ?? 'unauthenticated'} so React destroys and recreates it whenever the session changes.

Purpose: Stack.Protected in Expo Router expects only Stack.Screen children. Placing EventsProvider inside it prevents proper screen registration and guard-based redirect — causing two regressions: (1) no redirect to login after sign-out, (2) spurious "invite expired" error on login. The key prop approach achieves the same goal (fresh EventsProvider state on each session) without touching the navigation tree at all.

Output: _layout.tsx with EventsProvider back outside Stack.Protected, with key={session ?? 'unauthenticated'} added. Navigation works correctly. Events state resets on sign-out.
</objective>

The key prop works because React uses keys to identify component instances. When the key changes (session token → null on sign-out, or null → token on sign-in), React unmounts the old EventsProvider and mounts a fresh one with initialState (events: [], loading: false, error: null). This is identical in effect to the 19-04 approach but does not touch the navigation tree.
