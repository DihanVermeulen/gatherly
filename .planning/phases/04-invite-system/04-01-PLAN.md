  <action>
    Create `apps/api/src/routes/invites.ts` with these endpoints:

    **1. POST /api/events/:eventId/invites** (authenticateJWT required)
    - Generates a new invite for the event
    - Request body: `{ email?: string, expiresInDays?: number }` (both optional)
    - Generate invite code using `nanoid()` (21 chars, URL-safe)
    - If expiresInDays provided, calculate expires_at as NOW + expiresInDays days. Default: 30 days.
    - Insert into invites table: event_id, email (or null), invite_code, status='pending', expires_at
    - Build invite URL: `${process.env.FRONTEND_URL || 'http://localhost:3000'}/join/${inviteCode}`
    - Return 201: `{ id, inviteCode, inviteUrl, email, status, expiresAt, createdAt }`
    - Verify the event exists first (404 if not)

    **2. GET /api/events/:eventId/invites** (authenticateJWT required)
    - Returns all invites for the event with their status
    - Join with participants table to get participant name if accepted
    - Query: SELECT invites.*, participants.name as participant_name FROM invites LEFT JOIN participants ON invites.participant_id = participants.id WHERE invites.event_id = $1 ORDER BY invites.created_at DESC
    - Return 200: `{ invites: [...] }`

    **3. POST /api/invites/validate** (PUBLIC - no auth, rate limited)
    - Apply rate limiter: 10 requests per 15 minutes per IP
    - Request body: `{ code: string }`
    - Validate code length (must be exactly 21 characters)
    - Look up invite by code where status = 'pending' AND (expires_at IS NULL OR expires_at > NOW())
    - If not found: return 404 `{ error: "Invalid or expired invite" }` (generic message - don't reveal if expired vs not found)
    - If found: return 200 `{ eventId, eventName, inviteId }`

    **4. POST /api/invites/:code/accept** (PUBLIC - no auth, rate limited)
    - Apply same rate limiter
    - Request body: `{ participantName: string }`
    - Validate: code exists, status is 'pending', not expired
    - Use a database transaction:
      a. Check if participant name already exists in event (SELECT from participants WHERE event_id AND name)
      b. If participant exists, link invite to existing participant
      c. If participant doesn't exist, INSERT into participants table
      d. UPDATE invites SET status = 'accepted', participant_id = participantId WHERE invite_code = code
    - Return 200: `{ eventId, participantId, participantName, eventName }`
    - If invite not found/expired: return 404 `{ error: "Invalid or expired invite" }`

    **5. DELETE /api/events/:eventId/invites/:inviteId** (authenticateJWT required)
    - Delete/revoke an invite
    - Only delete if invite belongs to the specified event
    - Return 200: `{ message: "Invite revoked" }`

    **Rate limiter setup:**
    ```typescript
    import rateLimit from 'express-rate-limit';

    const inviteValidationLimiter = rateLimit({
      windowMs: 15 * 60 * 1000,
      max: 10,
      standardHeaders: true,
      legacyHeaders: false,
      handler: (req, res) => {
        res.status(429).json({ error: 'Too many requests, please try again later' });
      },
    });
    ```

    **Mount in server.ts:**
    - Import invitesRouter from './routes/invites'
    - Add `.use("/api", invitesRouter)` AFTER the auth routes line but BEFORE the 404 handler
    - Note: Routes are defined as `/events/:eventId/invites` and `/invites/validate` etc. in the router, so mounting at `/api` gives us `/api/events/:eventId/invites` and `/api/invites/validate`

    **Error handling pattern:** Follow the existing codebase pattern - wrap async handlers with try/catch, return appropriate HTTP status codes. Use the same `query` and `getClient` helpers from `../db/connection.js`.

    **IMPORTANT:** The API uses ESM (`"type": "module"`). Use `.js` extension in relative imports (e.g., `from '../db/connection.js'`). Follow the same import pattern as existing route files like `auth.ts`.
