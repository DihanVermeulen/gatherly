  <action>
Create the full wishlist page component that integrates all prior work.

**Route parameters:**
- `eventId` from URL params (`:eventId`)
- `participantId` from URL params (`:participantId`) — identifies current user
- Use `useParams()` from react-router to extract both

**Page structure (matching gift-registry.html layout):**

```
Top Navigation Bar (sticky)
  ← Back button | "Gift Registry" title + event name subtitle | Info button

Main content (scrollable, pb-24 for bottom nav clearance):
  Section: "Your Wishlist" header + "Visible to others" badge
  Carousel: Horizontal scroll of WishlistCard components + "Add More" placeholder
  Button: "Add Your First Gift" (shown when no items) or "Add to Wishlist"

  Section: "Registry" header + "Claim gifts to buy for others" subtitle
  For each participant (alphabetically, excluding current user):
    Participant header: initial avatar circle + "{Name}'s Wishlist"
    List of WishlistRegistryItem components
    Empty state if participant has no items
```

**Data flow:**
1. On mount, fetch wishlists from API: `wishlistsApi.getAll(eventId)`
2. Dispatch `SET_WISHLISTS` to update context state
3. Filter state for personal items: `wishlists.filter(w => w.participantId === parseInt(participantId))`
4. Group remaining items by participantName for registry section
5. Sort registry groups alphabetically by participant name

**Personal Wishlist Carousel:**
- Horizontal scrollable container: `flex overflow-x-auto hide-scrollbar gap-4 px-4 py-2`
- Map personal items to `<WishlistCard>` components
- "Add More" dashed placeholder card at end (same style as gift-registry.html):
  - `w-44 shrink-0 rounded-xl border-2 border-dashed border-gray-200 dark:border-gray-800 items-center justify-center p-4`
  - Plus icon in green circle + "Add More" text
  - onClick opens the form drawer
- Items ordered by most recently added first (createdAt DESC — already ordered from API)

**Add/Edit with WishlistForm drawer:**
- State: `isFormOpen` (boolean), `editingItem` (WishlistItem | null)
- "Add" button and "Add More" card set editingItem=null and open form
- "Edit" button on WishlistCard sets editingItem=item and opens form
- onSave handler:
  - If editingItem exists: call `wishlistsApi.update(eventId, editingItem.id, formData)`, dispatch UPDATE_WISHLIST_ITEM
  - If new: call `wishlistsApi.create(eventId, { participantId: parseInt(participantId), ...formData })`, dispatch ADD_WISHLIST_ITEM
  - Close form on success
  - If API fails (useApi=false or network error): create local item with temporary negative ID, dispatch to context (localStorage fallback)

**Delete functionality:**
Two methods (both per CONTEXT.md decisions):

1. **Swipe-to-delete on carousel cards:**
   - Wrap each WishlistCard in a swipe handler
   - Use touch events: onTouchStart, onTouchMove, onTouchEnd
   - Track swipe delta; if left swipe > 80px, reveal red delete button behind card
   - Delete button click: call delete API and dispatch DELETE_WISHLIST_ITEM
   - If item has claimedBy: show confirm dialog "Someone claimed this. Delete anyway?" before deleting

2. **Delete button in edit mode:**
   - Add a "Delete Item" button at bottom of WishlistForm when in edit mode (editItem is set)
   - Red/destructive styling: `text-red-500 font-bold`
   - Same claim check and confirm dialog as swipe delete

**Registry Section:**
- Group items by participantName (excluding current user's items)
- For each group:
  - Participant header: colored avatar circle (use first letter + deterministic color from name hash) + "{Name}'s Wishlist"
  - List of WishlistRegistryItem components
  - Set isClaimed based on whether item.claimedBy is truthy
  - onClaim prop: leave as no-op for now (Phase 3 will implement claiming)

**Empty states:**
- No personal items: Show "Add Your First Gift" button prominently (matches gift-registry.html)
- No registry items: Show subtle message "No other wishlists yet"
- Loading: Show loading skeleton (simple animated pulse placeholder cards)

**Error handling:**
- If API call fails: show error message with retry option
- If in offline mode (useApi=false): work with localStorage data, show subtle "Offline mode" indicator

**Styling details from gift-registry.html:**
- Top nav: `sticky top-0 z-10 flex items-center bg-background-light dark:bg-background-dark p-4 pb-2 justify-between border-b border-gray-200 dark:border-gray-800`
- Section headers: `text-[22px] font-bold leading-tight tracking-[-0.015em]`
- "Visible to others" badge: `text-xs font-semibold px-2 py-1 bg-primary/20 text-[#0d1b12] dark:text-primary rounded-full`
- Add button: `flex w-full cursor-pointer items-center justify-center rounded-xl h-12 px-4 bg-primary text-[#0d1b12] gap-2 text-sm font-bold shadow-lg shadow-primary/20`
- Registry subtitle: `text-sm text-gray-500`
- Participant avatar: `size-8 rounded-full flex items-center justify-center overflow-hidden border border-white` with deterministic background color
- Hide scrollbar: use `.hide-scrollbar` CSS class (already defined in global.css or add utility)

**Navigation:**
- Back button: use `useNavigate()` from react-router, navigate(-1) or to `/events/edit/${eventId}`
- Use Lucide React icons: ArrowLeft for back, Plus for add, Info for info
