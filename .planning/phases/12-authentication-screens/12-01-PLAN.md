**Step 3: Update auth.ts — add refreshToken to refresh() call body**

The `authApi.refresh()` function currently sends an empty POST. Update it to optionally accept a refreshToken parameter and send it in the body:
```typescript
async refresh(refreshToken?: string): Promise<AuthResponse> {
  const response = await apiClient.post<AuthResponse>("/api/auth/refresh",
    refreshToken ? { refreshToken } : undefined
  );
  return response.data;
}
```

**Step 4: Rewrite AuthContext.tsx with SecureStore persistence**

Replace the entire stub with a full implementation:

- Import `* as SecureStore from 'expo-secure-store'`
- Import `setAccessToken, setSignOutCallback` from `../api/client`
- Import `authApi, User` from `../api/auth`

Type changes:
```typescript
type AuthContextValue = {
  session: string | null;          // accessToken (kept for Stack.Protected guard compatibility)
  user: User | null;
  isLoading: boolean;
  signIn: (accessToken: string, refreshToken: string, user: User) => Promise<void>;
  signOut: () => Promise<void>;
};
```

Constants:
```typescript
const ACCESS_TOKEN_KEY = 'gatherly_access_token';
const REFRESH_TOKEN_KEY = 'gatherly_refresh_token';
const USER_KEY = 'gatherly_user';
```

SessionProvider implementation:
1. `isLoading` starts as `true`
2. On mount (useEffect), attempt silent refresh:
   - Read refreshToken from SecureStore
   - If found, call `authApi.refresh(refreshToken)`
   - On success: store new tokens in SecureStore, set session/user state, call `setAccessToken(response.accessToken)`
   - On failure: clear all SecureStore keys, set session to null
   - In finally: set `isLoading = false`
3. `signIn`: stores accessToken + refreshToken + JSON.stringify(user) in SecureStore, updates state, calls `setAccessToken`
4. `signOut`: calls `authApi.logout()` (wrapped in try/catch — don't fail if API unreachable), deletes all 3 SecureStore keys, calls `setAccessToken(null)`, sets session/user to null
5. Register `setSignOutCallback(signOut)` in a useEffect so the interceptor can trigger logout on unrecoverable 401

IMPORTANT: The `session` field must remain a string|null because `_layout.tsx` uses `!!session` as the Stack.Protected guard. Set it to the accessToken string on login, null on logout.

**Form behavior:**
- State: `email`, `password`, `showPassword`, `isSubmitting`, `error` (string|null)
- On submit: validate email is non-empty and password is non-empty. Show inline error text (red, below the form or above the button) if validation fails or API returns error.
- Call `authApi.login(email, password)`. On success, call `signIn(response.accessToken, response.accessToken, response.user)` from useSession(). NOTE: The backend returns accessToken but the refreshToken is set via HttpOnly cookie. For the SecureStore flow, pass the accessToken as the refreshToken parameter too — the AuthContext stores it, and the real refresh flow uses the cookie on web but the stored token on mobile. ACTUALLY: Looking at the backend response more carefully — login/register only return `{ accessToken, user }`. The refreshToken is ONLY in the Set-Cookie header. Since React Native may not reliably persist cookies, we need to extract it. However, the current authApi doesn't return it. The simplest approach: after login succeeds, the session is established via cookie for the current app session. On app restart, if the cookie is gone, the stored accessToken will be expired and refresh will fail. To fix this properly, we need the backend to ALSO return the refreshToken in the response body. BUT that's a bigger change. For NOW: store only the accessToken in SecureStore, and on app restart, attempt refresh with the cookie first. If that fails AND we have a stored token, try sending it in the body (this is what Plan 12-02's backend change enables). For this plan, implement signIn as `signIn(accessToken: string, user: User)` — simpler signature, store accessToken in SecureStore.

REVISED AuthContext signIn signature (simpler, matches what backend actually returns):

signIn: (accessToken: string, user: User) => Promise<void>;

And in the silent refresh on mount, store the NEW accessToken from the refresh response.
