**Step 2: Fix client.ts — replace window.location.href with signOutCallback pattern + router redirect**

```typescript
import { router } from 'expo-router';
```

Add at module level (after the existing token management):
```typescript
let _signOutCallback: (() => Promise<void>) | null = null;
export const setSignOutCallback = (fn: () => Promise<void>) => { _signOutCallback = fn; };
```

In the catch block of the 401 interceptor (line ~110-115), replace:
```typescript
window.location.href = "/login";
```
with:
```typescript
if (_signOutCallback) await _signOutCallback();
router.replace('/sign-in');
```

The `router.replace('/sign-in')` MUST come AFTER the `_signOutCallback()` call, not before. The callback clears SecureStore state; the redirect navigates to login.

Also change `VITE_API_URL` to `EXPO_PUBLIC_API_URL` (Expo convention, not Vite). The env var reference on line 3 should be:
```typescript
const API_BASE_URL = process.env.EXPO_PUBLIC_API_URL || "http://localhost:5001";
```

**Step 3: Update auth.ts — add refreshToken to refresh() call body**

The `authApi.refresh()` function currently sends an empty POST. Update it to optionally accept a refreshToken parameter and send it in the body:
```typescript
async refresh(refreshToken?: string): Promise<AuthResponse> {
  const response = await apiClient.post<AuthResponse>("/api/auth/refresh",
    refreshToken ? { refreshToken } : undefined
  );
  return response.data;
}
```

**Step 4: Rewrite AuthContext.tsx with SecureStore persistence**

Replace the entire stub with a full implementation:

- Import `* as SecureStore from 'expo-secure-store'`
- Import `setAccessToken, setSignOutCallback` from `../api/client`
- Import `authApi, User` from `../api/auth`

Type changes — use the 2-arg signIn signature (the backend only returns `{ accessToken, user }` in the response body; the refreshToken is HttpOnly cookie only):
```typescript
type AuthContextValue = {
  session: string | null;          // accessToken (kept for Stack.Protected guard compatibility)
  user: User | null;
  isLoading: boolean;
  signIn: (accessToken: string, user: User) => Promise<void>;
  signOut: () => Promise<void>;
};
```

Constants:
```typescript
const ACCESS_TOKEN_KEY = 'gatherly_access_token';
const USER_KEY = 'gatherly_user';
```

Note: No REFRESH_TOKEN_KEY — the refreshToken lives only in the HttpOnly cookie. We store only the accessToken and user in SecureStore.

SessionProvider implementation:
1. `isLoading` starts as `true`
2. On mount (useEffect), attempt silent refresh:
   - Call `authApi.refresh()` (no body token — relies on cookie)
   - On success: store new accessToken + user in SecureStore, set session/user state, call `setAccessToken(response.accessToken)`
   - On failure: clear all SecureStore keys, set session to null
   - In `finally` block: set `isLoading = false` (this MUST always fire regardless of success/failure)
3. `signIn(accessToken: string, user: User)`: stores accessToken + JSON.stringify(user) in SecureStore, updates state, calls `setAccessToken(accessToken)`
4. `signOut`: calls `authApi.logout()` (wrapped in try/catch — don't fail if API unreachable), deletes all SecureStore keys, calls `setAccessToken(null)`, sets session/user to null
5. Register `setSignOutCallback(signOut)` in a useEffect so the interceptor can trigger logout on unrecoverable 401

IMPORTANT: The `session` field must remain a string|null because `_layout.tsx` uses `!!session` as the Stack.Protected guard. Set it to the accessToken string on login, null on logout.

IMPORTANT: `signIn` signature is `(accessToken: string, user: User)` — exactly 2 arguments. Do NOT add a refreshToken parameter. The backend does not return refreshToken in the response body (it is HttpOnly cookie only).
