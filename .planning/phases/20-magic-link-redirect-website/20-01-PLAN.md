**Deployment note** (add as a comment block at the top of each file using a wrapper approach): CRA's `react-scripts` serves files from `public/` as-is but cannot set custom response headers. The AASA file MUST be served with `Content-Type: application/json` for iOS Universal Links to work. The hosting platform (Netlify, Vercel, nginx) must be configured to add this header. Example Netlify `_headers` config if applicable:
```
/.well-known/apple-app-site-association
  Content-Type: application/json
```
JSON does not support comments, so add a companion `README.md` in `public/.well-known/` explaining the Content-Type requirement.

# .well-known verification files

These files support iOS Universal Links (AASA) and Android App Links (assetlinks.json).

## IMPORTANT: Content-Type header required

The apple-app-site-association file MUST be served with:
  Content-Type: application/json

CRA (react-scripts) cannot set custom headers. Configure at your hosting platform:

Rewrite `apps/gatherly/src/pages/magic-link.tsx` to remove all custom scheme (`gatherly://`) logic. With Universal Links in place, the OS handles routing to the app — the web page only loads as a fallback when the app is not installed, so it should authenticate immediately without any deep link attempt or timeout.

**Remove:**
- `const APP_OPEN_TIMEOUT_MS = 2000;`
- `window.location.href = \`gatherly://magic-link/${token}\`;`
- The `setTimeout` / `timer` / `clearTimeout` logic
- The `hasRedeemed` ref (no longer needed)

**Replace the useEffect with:**
```tsx
useEffect(() => {
  if (!token) {
    navigate("/home");
    return;
  }

  // Universal Links handle app routing at the OS level.
  // This page only loads when the app is NOT installed — authenticate directly.
  loginWithMagicLink(token)
    .then(() => setPageState("success"))
    .catch((err: any) => {
      const status = err.response?.status;
      if (status === 429) {
        setPageState("rate-limited");
      } else {
        setPageState("invalid");
      }
    });
}, [token, navigate, loginWithMagicLink]);
```

**Update the "redeeming" loading state** — remove the misleading "Please wait..." which implied it was waiting for the app to open. Replace with:
```tsx
<p className="">Authenticating...</p>
```

Keep all other UI states (success, invalid, rate-limited) exactly as they are. Do not change imports, component structure, or styling.

Remove unused imports if `useRef` becomes unused after removing `hasRedeemed`.
