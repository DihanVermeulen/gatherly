In `apps/api/src/routes/magicLink.ts`, add a new POST `/lookup` route BEFORE the existing `/redeem` route. This endpoint:

1. Accepts `{ token: string }` in request body
2. Validates token is non-empty string
3. Hashes the token with SHA-256 (same as /redeem)
4. Looks up `magic_link_tokens` where `token_hash = $1 AND expires_at > NOW()` to get `invite_id`
5. If not found, return 401 `{ error: "Invalid or expired magic link" }`
6. JOINs `invites`, `events`, and LEFT JOINs `users` (via `invites.created_by_user_id`) to get:
   - `invites.invite_code` (the 21-char nanoid)
   - `invites.event_id`
   - `invites.email` as `invite_email`
   - `events.name` as `event_name`
   - `events.event_date`
   - `users.name` as `organizer_name`
   - Subquery: `(SELECT COUNT(*) FROM participants WHERE event_id = events.id)` as `participant_count`
7. Returns 200 JSON:
```json
{
  "eventId": number,
  "eventName": string,
  "inviteCode": string,
  "organizerName": string | null,
  "participantCount": number,
  "eventDate": string | null,
  "inviteEmail": string | null
}
```

Apply the same `redeemRateLimiter` to this endpoint (reuse the existing rate limiter instance).

Do NOT create a participant, do NOT modify the invite status, do NOT issue a JWT. This is read-only.

In `apps/gatherly-mobile/app/api/auth.ts`, add a `lookupMagicLink` method to `authApi`:

```typescript
export interface MagicLinkPreview {
  eventId: number;
  eventName: string;
  inviteCode: string;
  organizerName: string | null;
  participantCount: number;
  eventDate: string | null;
  inviteEmail: string | null;
}

async lookupMagicLink(token: string): Promise<MagicLinkPreview> {
  const response = await apiClient.post<MagicLinkPreview>(
    "/api/auth/magic-link/lookup",
    { token }
  );
  return response.data;
}
```
