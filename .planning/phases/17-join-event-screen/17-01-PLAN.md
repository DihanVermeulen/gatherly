    **Part A: Extend backend validate endpoint (`apps/api/src/routes/invites.ts`)**

    The current validate endpoint (POST /invites/validate, ~line 178) returns only `{ eventId, eventName, inviteId }`. The CONTEXT requires the event preview to show organizer name, participant count, and event date. Extend the SQL query and response.

    The `events` table has no `created_by` column, and `invites` has no `created_by_user_id`. The pragmatic solution: the invite is always created by the organizer (authenticated via `authenticateJWT`). Add the invite creator's identity to the response by:

    1. Add a `created_by_user_id INTEGER REFERENCES users(id)` column to the invites table. In the validate endpoint handler, before the main query, run a one-time migration-safe ALTER:
       - Do NOT add an ALTER TABLE in the route handler. Instead, update the INSERT in the `POST /events/:eventId/invites` endpoint (~line 66) to also store `created_by_user_id`:
         ```sql
         INSERT INTO invites (event_id, email, invite_code, status, expires_at, created_by_user_id)
         VALUES ($1, $2, $3, $4, $5, $6)
         RETURNING id, event_id, email, invite_code, status, expires_at, created_at
         ```
         Where `$6` is `(req as any).user.id` (the authenticated user's ID from the JWT middleware).

    2. The column needs to exist first. Add it via a SQL migration file OR, since this project uses `schema.sql` directly, update `apps/api/src/db/schema.sql` to add the column to the invites CREATE TABLE:
       ```sql
       created_by_user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
       ```
       Place it after the `participant_id` line in the invites table definition.

    3. Update the validate endpoint SQL query (~line 190) to also join users and count participants:
       ```sql
       SELECT
         invites.id as invite_id,
         invites.event_id,
         events.name as event_name,
         events.created_at as event_date,
         users.name as organizer_name,
         (SELECT COUNT(*) FROM participants WHERE participants.event_id = events.id) as participant_count
       FROM invites
       JOIN events ON invites.event_id = events.id
       LEFT JOIN users ON invites.created_by_user_id = users.id
       WHERE invites.invite_code = $1
         AND invites.status = 'pending'
         AND (invites.expires_at IS NULL OR invites.expires_at > NOW())
       ```

    4. Update the validate response (~line 210) to return the additional fields:

    **Part C: Create pendingInvite utility (`apps/gatherly-mobile/app/utils/pendingInvite.ts`)**

    Create the `utils/` directory if it does not exist. This is a module-level variable utility for preserving the invite code across auth navigation. NOT AsyncStorage — a simple module variable that persists within the same JS session.

    ```typescript
    // Module-level variable — persists across component remounts within same session
    let _pendingInviteCode: string | null = null;

    export function setPendingInviteCode(code: string): void {
      _pendingInviteCode = code;
    }

    export function consumePendingInviteCode(): string | null {
      const code = _pendingInviteCode;
      _pendingInviteCode = null;
      return code;
    }
    ```

    1. Add import at top of file:

       ```typescript
       import { consumePendingInviteCode } from "./utils/pendingInvite";
       ```
       Note: `useRouter` may already be available via expo-router. If `router` is already imported, use that instead.

    2. Inside `RootLayoutNav`, after the existing `useEffect` for SplashScreen (~line 49), add:
       ```typescript
       const router = useRouter();

       // After authentication, check for pending invite code and redirect to join screen.
       // This handles the race condition where Stack.Protected redirects away from
       // sign-in/register before they can navigate to /join themselves.
       useEffect(() => {
         if (session && !isLoading) {
           const pendingCode = consumePendingInviteCode();
           if (pendingCode) {
             // Small delay to let the Stack.Protected navigation settle
             const timer = setTimeout(() => {
               router.replace(`/join?token=${pendingCode}`);
             }, 100);
             return () => clearTimeout(timer);
           }
         }
       }, [session, isLoading]);
       ```

       IMPORTANT: This effect fires when `session` transitions from null to truthy (after successful auth). The `consumePendingInviteCode()` call is atomic — it reads and clears the value — so this only triggers once. The 100ms delay ensures the Stack.Protected guard has finished its redirect before we navigate to /join. The join screen is a PUBLIC route (outside both Stack.Protected blocks), so it's accessible regardless of auth state.
