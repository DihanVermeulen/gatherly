    apps/api/src/routes/events.ts

  <action>
    Import authenticateJWT and optionalAuth from '../middleware/auth' in each route file. Apply middleware to routes following the zero trust principle:

    **events.ts:**
    - GET / (list events): Use `optionalAuth` - events should be listable without auth during migration, but if authenticated, can filter by user's events
    - POST / (create event): Use `authenticateJWT` - must be logged in to create events
    - GET /:id (get single event): Use `optionalAuth` - accessible but could show more detail to authenticated users
    - PUT /:id (update event): Use `authenticateJWT` - must be logged in
    - DELETE /:id (delete event): Use `authenticateJWT` - must be logged in
    - POST /:id/participants: Use `authenticateJWT`
    - DELETE /:id/participants/:participantId: Use `authenticateJWT`
    - POST /:id/couples: Use `authenticateJWT`
    - DELETE /:id/couples/:coupleId: Use `authenticateJWT`
    - POST /:id/generate (generate assignments): Use `authenticateJWT`
    - GET /:id/codes: Use `authenticateJWT`
    - Apply middleware as route-level middleware, not globally on router. Example: `router.get('/', optionalAuth, async (req, res) => { ... })`
    - Do NOT change any existing route handler logic. Only add the middleware parameter.

    **wishlists.ts:**
    - All routes: Use `authenticateJWT` - wishlists are personal, always require auth
    - Apply to GET, POST, PUT, DELETE routes

    **gifts.ts:**
    - GET routes: Use `optionalAuth` - viewing gifts can be public
    - POST, PUT, DELETE, claiming routes: Use `authenticateJWT` - modifying gifts requires auth

    IMPORTANT: Read each route file first to understand the exact route definitions before modifying. Do not change handler implementations, only add middleware parameters.

    - No handler logic was changed (only middleware added)
  </verify>
