<task type="auto">
  <name>Task 2: Create token service and authentication middleware</name>
  <files>
    apps/api/src/services/tokenService.ts

  </files>
  <action>
    1. Create `apps/api/src/services/tokenService.ts`:
       - Import jsonwebtoken, crypto, and query from db/connection
       - Define TokenPayload interface: { userId: number; email: string; role: 'organizer' | 'participant' }
       - Read JWT_SECRET and REFRESH_SECRET from process.env (with fallback error if missing)
       - `generateTokens(payload: TokenPayload)`: Sign access token with JWT_SECRET, expiresIn '15m', algorithm 'HS256'. Sign refresh token with REFRESH_SECRET, expiresIn '7d', algorithm 'HS256', jwtid: crypto.randomUUID(). Store refresh token hash (use crypto.createHash('sha256').update(refreshToken).digest('hex')) in refresh_tokens table with user_id and expires_at (7 days from now). Return { accessToken, refreshToken }.
       - `verifyAccessToken(token: string)`: jwt.verify with JWT_SECRET, algorithms: ['HS256']. Returns TokenPayload.
       - `verifyRefreshToken(token: string)`: jwt.verify with REFRESH_SECRET, algorithms: ['HS256']. Then check if token hash exists in refresh_tokens table and is not expired. Returns TokenPayload or throws.
       - `blacklistToken(token: string)`: Decode token to get exp, compute TTL remaining, store in a `blacklisted_tokens` row (or simply use a lightweight approach: store token hash in refresh_tokens-style table with TTL). SIMPLER APPROACH: Since we use PostgreSQL not Redis, implement blacklisting by adding a `blacklisted_tokens` table check. Actually, for simplicity in Phase 7, skip blacklisting and rely on short-lived access tokens (15min). Document this as a future enhancement.
       - `revokeRefreshToken(tokenHash: string)`: DELETE from refresh_tokens WHERE token_hash = $1
       - `revokeAllUserTokens(userId: number)`: DELETE from refresh_tokens WHERE user_id = $1
       - `cleanExpiredTokens()`: DELETE from refresh_tokens WHERE expires_at < NOW(). Call this periodically or on refresh.
       - Export all functions.

    2. Create `apps/api/src/middleware/auth.ts`:
       - Import express Request, Response, NextFunction types
       - Import verifyAccessToken from services/tokenService
       - Import jsonwebtoken for error types (JsonWebTokenError, TokenExpiredError)
       - Extend Express Request interface globally: add `user?: { userId: number; email: string; role: 'organizer' | 'participant' }`
       - `authenticateJWT` middleware: Extract Bearer token from Authorization header. If missing, return 401 { error: 'No token provided' }. Call verifyAccessToken(token). If valid, set req.user = { userId, email, role } and call next(). Catch JsonWebTokenError -> 401 'Invalid token'. Catch TokenExpiredError -> 401 'Token expired'. Catch other -> 500 'Authentication failed'.
       - `optionalAuth` middleware: Same as authenticateJWT but if no token, just call next() without setting req.user. If token invalid, still call next() without user (swallow error). This enables gradual migration.
       - Export both middleware functions.
       - Do NOT use `return res.status()` pattern that conflicts with Express types. Use `res.status().json(); return;` pattern instead to avoid TypeScript issues.
  </action>
