  <action>
    1. Create `apps/gatherly/src/api/auth.ts`:
       - Import apiClient from './client'
       - Define User interface: { id: number; email: string; name: string; role: 'organizer' | 'participant' }
       - Define AuthResponse interface: { accessToken: string; user: User }
       - Export authApi object with:
         - `login(email: string, password: string): Promise<AuthResponse>` -> POST /api/auth/login with { email, password }. Return response.data.
         - `register(email: string, password: string, name: string): Promise<AuthResponse>` -> POST /api/auth/register with { email, password, name }. Return response.data.
         - `refresh(): Promise<AuthResponse>` -> POST /api/auth/refresh (no body, cookie sent automatically). Return response.data.
         - `logout(): Promise<void>` -> POST /api/auth/logout (no body, cookie sent automatically).

    2. Update `apps/gatherly/src/api/client.ts`:
       - Add `withCredentials: true` to axios.create config (required for HttpOnly cookies to be sent cross-origin)
       - Add a request interceptor that reads access token from a module-level variable (NOT localStorage per research anti-patterns). Export `setAccessToken(token: string | null)` and `getAccessToken(): string | null` functions that manage a module-level `let _accessToken: string | null = null`. The request interceptor reads from `_accessToken` and sets Authorization header if present.
       - Add a response interceptor for 401 handling: When response is 401 and request hasn't been retried (_retry flag), set isRefreshing flag, call authApi.refresh(), update _accessToken, retry original request. Use queue pattern for concurrent requests during refresh (see research Pattern: Axios Client with Auto Token Refresh). If refresh fails, clear _accessToken, redirect to /login via window.location.href = '/login'.
       - IMPORTANT: Import authApi lazily inside the interceptor to avoid circular dependency (client.ts <-> auth.ts). Use dynamic import or restructure: put setAccessToken/getAccessToken in client.ts, keep auth API calls in auth.ts.

    3. Create `apps/gatherly/src/contexts/AuthContext.tsx`:
       - Define User type (same as auth.ts, or import from shared types)
       - Define AuthContextValue: { user: User | null; isLoading: boolean; login(email: string, password: string): Promise<void>; register(email: string, password: string, name: string): Promise<void>; logout(): Promise<void> }
       - Create AuthContext with createContext
       - Create AuthProvider component:
         - State: user (User | null), isLoading (boolean, starts true)
         - On mount (useEffect): try authApi.refresh() to restore session from HttpOnly cookie. On success, set user and call setAccessToken. On failure, set user null. Always set isLoading false.
         - login function: call authApi.login, call setAccessToken with response.accessToken, set user from response.user
         - register function: call authApi.register, call setAccessToken with response.accessToken, set user from response.user
         - logout function: call authApi.logout, call setAccessToken(null), set user to null
         - Auto-refresh interval: When user is set and accessToken exists, set interval to call authApi.refresh() every 14 minutes (1 minute before 15min expiry). Clear interval on unmount or when user becomes null.
       - Export useAuth hook: `const useAuth = () => useContext(AuthContext)`
       - Export AuthProvider and AuthContext
  </action>

    - auth.ts exports authApi with login, register, refresh, logout
    - client.ts exports setAccessToken, getAccessToken
    - AuthContext.tsx exports AuthProvider, useAuth
    - No circular dependency errors at build time
  </verify>
