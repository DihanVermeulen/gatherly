    1. Update `auth.ts` POST /register:
       - After the INSERT INTO users query (around line 74, after `const user = result.rows[0]`), add participant linking:
         ```sql
         UPDATE participants SET user_id = $1
         WHERE id IN (
           SELECT p.id FROM participants p
           JOIN invites i ON i.participant_id = p.id
           WHERE LOWER(i.email) = $2
             AND i.status = 'accepted'
             AND p.user_id IS NULL
         )
         ```
         Pass `[user.id, email.toLowerCase()]` as params.
       - This is fire-and-forget style: wrap in try/catch, log errors but do not fail registration if linking fails. Registration must always succeed even if linking has issues.
       - Place this BEFORE generateTokens so it happens within the same request but does not block the response on failure.

    2. Update `events.ts` GET /api/events:
       - In the organizer branch (the `else` block around line 63-67), change the WHERE clause from:
         ```sql
         WHERE e.organizer_id = $1 OR e.organizer_id IS NULL
         ```
         to:
         ```sql
         WHERE e.organizer_id = $1
            OR e.organizer_id IS NULL
            OR EXISTS (
              SELECT 1 FROM participants p2
              WHERE p2.event_id = e.id AND p2.user_id = $1
            )
         ```
         The parameter `$1` is already `user.userId`. The GROUP BY e.id already handles deduplication.
       - Do NOT change the participant branch (magic-link participants still see only their one event via eventId).
  </action>
