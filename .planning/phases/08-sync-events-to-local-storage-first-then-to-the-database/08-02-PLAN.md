   - Import `useMutation, useQueryClient` from `@tanstack/react-query`
   - Import `eventsApi, Event` from `../api/events`

   Export `useCreateEvent()`:
   - `mutationKey: ['event', 'create']`
   - `mutationFn`: takes `{ name: string; coupleCrossing: boolean }`, calls `eventsApi.create(name, coupleCrossing)`
   - `onMutate`: Cancel queries for `['events']`, snapshot previous, optimistically append a temp event with `id: 'temp-' + Date.now()`, `name`, `coupleCrossing`, empty arrays for people/participants/couples, null assignments, empty gifts object, current date ISO, empty wishlists. Return `{ previous }`.
   - `onError`: Rollback to previous snapshot
   - `onSuccess`: Replace temp event (id starts with 'temp-') with real server response
   - `onSettled`: Invalidate `['events']` queries

   Export `useUpdateEvent()`:
   - `mutationKey: ['event', 'update']`
   - `mutationFn`: takes `Event`, calls `eventsApi.update(event.id, event)` (pass the full event minus id as the body)
   - `onMutate`: Cancel queries, snapshot, optimistically replace matching event in cache
   - `onError`: Rollback
   - `onSettled`: Invalidate `['events']`

   Export `useDeleteEvent()`:
   - `mutationKey: ['event', 'delete']`
   - `mutationFn`: takes `string` (id), calls `eventsApi.delete(id)`
   - `onMutate`: Cancel queries, snapshot, optimistically filter out event
   - `onError`: Rollback
   - `onSettled`: Invalidate `['events']`

   IMPORTANT: All mutations use `queryClient.setQueryData<Event[]>(['events'], ...)` for optimistic updates. Always handle the case where `old` is undefined by defaulting to `[]`.

Refactor `EventsContext.tsx` to use TanStack Query hooks internally while keeping the EXACT same public interface that all page components depend on: `{ state: { events, loading, error }, dispatch, refreshEvents, useApi }`.

Strategy: The context becomes a thin adapter. Internally it uses `useEventsQuery()` for data and `useCreateEvent/useUpdateEvent/useDeleteEvent` for mutations. Externally it still exposes the same `state + dispatch + refreshEvents + useApi` shape.

Implementation:

1. Remove the `useReducer` and the old `eventsReducer` function entirely.
2. Remove the old `checkApi` useEffect and the `STORAGE_KEY` constant.
3. Remove the old localStorage save useEffect.

4. Inside `EventsProvider`:
   - Call `useEventsQuery()` to get `{ data: events, isLoading, error, refetch }`
   - Call `useCreateEvent()`, `useUpdateEvent()`, `useDeleteEvent()` to get mutation objects
   - Derive `useApi` from whether the query succeeded from network (check `status === 'success'`). For backward compat, set `useApi = true` since we are always attempting API with offline-first fallback. The concept of "useApi" is less meaningful now, but pages check it, so keep it as `true` (TanStack Query handles the offline case transparently).

5. Build the `state` object from query data:
   ```typescript
   const state: EventsState = {
     events: (events || []).map(e => ({
       ...e,
       wishlists: e.wishlists || [],
       gifts: e.gifts || {},
     })),
     loading: isLoading,
     error: error ? error.message : null,
   };
   ```

6. Create a `dispatch` wrapper function that maps old action types to new mutation calls:
   ```typescript
   const dispatch = (action: EventsAction) => {
     switch (action.type) {
       case 'ADD_EVENT':
         createMutation.mutate({
           name: action.payload.name,
           coupleCrossing: action.payload.coupleCrossing || false,
         });
         break;
       case 'UPDATE_EVENT':
         updateMutation.mutate(action.payload);
         break;
       case 'DELETE_EVENT':
         deleteMutation.mutate(action.payload); // payload is the id string
         break;
       case 'SET_EVENTS':
         // Handled by TanStack Query cache - ignore manual SET_EVENTS
         break;
       case 'SET_LOADING':
       case 'SET_ERROR':
         // Handled by TanStack Query state - ignore
         break;
       // Wishlist actions - for now, update the event directly via update mutation
       case 'ADD_WISHLIST_ITEM':
       case 'UPDATE_WISHLIST_ITEM':
       case 'DELETE_WISHLIST_ITEM':
       case 'SET_WISHLISTS':
         // These operate on sub-resources. For now, manually update the query cache:
         // Use queryClient.setQueryData to update the events array optimistically
         // This preserves existing wishlist functionality without needing new API hooks
         handleWishlistAction(action);
         break;
     }
   };
   ```

7. For wishlist actions, create a `handleWishlistAction` helper that uses `useQueryClient().setQueryData` to modify the cached events array. This is a cache-only update since wishlist operations already have their own API calls in the page components. The pattern:
   ```typescript
   const queryClient = useQueryClient();
   function handleWishlistAction(action: EventsAction) {
     queryClient.setQueryData<Event[]>(['events'], (old = []) => {
       // Apply the same reducer logic as before, but on the cache
       switch (action.type) {
         case 'ADD_WISHLIST_ITEM':
           return old.map(e => e.id === action.payload.eventId
             ? { ...e, wishlists: [action.payload.item, ...(e.wishlists || [])] }
             : e);
         case 'UPDATE_WISHLIST_ITEM':
           return old.map(e => e.id === action.payload.eventId
             ? { ...e, wishlists: (e.wishlists || []).map(item =>
                 item.id === action.payload.item.id ? action.payload.item : item) }
             : e);
         case 'DELETE_WISHLIST_ITEM':
           return old.map(e => e.id === action.payload.eventId
             ? { ...e, wishlists: (e.wishlists || []).filter(
                 item => item.id !== action.payload.itemId) }
             : e);
         case 'SET_WISHLISTS':
           return old.map(e => e.id === action.payload.eventId
             ? { ...e, wishlists: action.payload.items }
             : e);
         default:
           return old;
       }
     });
   }
   ```
