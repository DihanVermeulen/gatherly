## E2E Flow Analysis

### Flow 1: New User Join via Magic Link ✅ Connected
Email invite → magic-link webpage → deep link → `[token].tsx` → lookup preview → redeem → `signIn()` + `refreshEvents()` → event-details. Fully wired.

### Flow 2: Full Gift Exchange ✅ Connected
Create event → add participants → generate assignments → view event-details → browse wishlists → claim gifts. All route registrations, context dispatches, and API calls verified.

### Flow 3: Organizer Invite Management ✅ Connected
Add participant → invite created (`POST /api/events/:id/invites`) → Invites card in edit-event.tsx → resend (`POST .../resend-magic-link`) / revoke (`DELETE .../invites/:id`). All three backend endpoints exist and are protected.

### Flow 4: Account Linking ✅ Connected
Magic-link participant → registers → `POST /auth/register` links participants by email → GET /events returns participant-linked events → appears in list.

### Flow 5: QR Code / Invite URL Join ⚠ BROKEN
`join.tsx` `handleJoin()` calls `invitesApi.accept()` → sets `joinedEventId` → `setJoinState("success")`. **Missing: `refreshEvents()` before success state.** After 2s auto-navigation to `/event-details?id=...`, the event may not exist in EventsContext, causing "Event not found." Compare: magic-link flow in `[token].tsx` line 136 correctly calls `await refreshEvents()` before success.

**File:** `apps/gatherly-mobile/app/join.tsx` line ~119
**Fix:** Add `await refreshEvents()` after `invitesApi.accept()` resolves, before `setJoinState("success")`

```
File: apps/gatherly-mobile/app/join.tsx

Expected: await refreshEvents() called before setJoinState("success")
Actual: setJoinState("success") called with no prior refreshEvents()
Impact: User joins via QR code/invite URL, navigates to event-details, event not in EventsContext → "Event not found" state
```
