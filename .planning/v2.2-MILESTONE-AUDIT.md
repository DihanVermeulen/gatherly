## Integration Gaps

### GAP 1 — Events List Cover Photo (Medium)

**From:** Phase 30 (`hasCoverPhoto: boolean` on TEvent list response)
**To:** Phase 32 (events list EventCard in `(tabs)/index.tsx`)
**Issue:** `EventCard` always renders a `LinearGradient` hero regardless of `hasCoverPhoto`. There is no conditional `Image` branch when `hasCoverPhoto === true`. Cover photos are only visible after tapping into event-details, not from the list.
**Missing:** A conditional `Image` source render in EventCard when `item.hasCoverPhoto` is true (requires a `coverPhotoUrl` from getById, or a separate thumbnail endpoint).
**Impact:** Display gap only — no crash, no data loss. Events list looks consistent (always teal gradient) but doesn't preview cover photos.

### GAP 2 — Onboarding Bypass via Post-Registration Deep-Link (Medium)

**From:** Phase 31 (onboarding guard in `(tabs)/index.tsx`)
**To:** `_layout.tsx` post-auth redirect (lines 71–91)
**Issue:** After registration, if a pending invite code or magic token is present, `_layout.tsx` redirects the user to `/join` or `/magic-link/:token` before the `(tabs)` screen mounts. The `(tabs)/index.tsx` `useEffect` guard that checks `user.onboardingComplete === false` never runs. New users arriving via invite links at registration time skip onboarding.
**Missing:** An `onboardingComplete` check in `_layout.tsx`'s post-auth `useEffect` before the pending-invite/magic-token redirects execute.
**Impact:** New users who registered from an event invite link skip the onboarding flow on first run. They will see onboarding next time they navigate to the tabs (guard will catch them), but the ordering is inconsistent.

## Tech Debt

### Phase 31 — Onboarding Screens

- **Gift Preferences cosmetic field:** `profile-setup.tsx` renders a "Gift Preferences" text field that is not persisted to the API (no `gift_preferences` DB column). Wired visually but sends nothing. Tagged for future phase when column is added.
- **Type mismatch `User` vs `UserProfile`:** `User.onboardingComplete` is `boolean?` (optional) while `UserProfile.onboardingComplete` is `boolean` (required). No runtime impact due to spread merge in `updateUser`. Needs unification in a cleanup pass.

### Phase 33 — Potluck Screens

- **Silent catch in `saveCategory`** (`potluck-setup.tsx` line 178): Category save failures are silently swallowed. User can retry by editing the field again. No toast shown.
- **Silent catch in `pickFoodImage`** (`potluck-setup.tsx` line 259): Image pick failures are silently swallowed. Low severity; image is optional.

**Total tech debt: 4 items across 2 phases**
