# Milestone v2.3: Pricing Plans

**Status:** ✅ SHIPPED 2026-04-08
**Phases:** 34–38
**Total Plans:** 9

## Overview

Implement a per-event upgrade model with full paywall UX — locked feature screens, trial limits, pricing/plans page, and a stub payment CTA — without real billing integration. Free events get trial access to premium modules with defined limits (20 participants, 3 potluck categories, 1 poll); paid events unlock everything. Upgrade demand captured via external Typeform CTA; Stripe integration deferred to v2.4.

## Phases

## Milestone Summary

**Key Decisions:**

- `planTier: 'free' | 'premium'` — 'standard' removed; 'premium' is the single upgrade tier
- `PREMIUM_MODULES = ["white_elephant"]` — polls/potluck/rsvp gated at usage level (creation endpoints), not module-enable level; allows free users to configure modules, fail gracefully on overcap
- External Typeform for upgrade demand capture — no in-app upgrade_requests table; zero backend work; URL as app constant
- PaywallBanner uses Pressable + native Text for CTA — inline amber hex (#f59e0b, #78350f) conflict with NativeWind variant system; GlueStack Button not used here
- PaywallModal pattern: `useState<PaywallFeature | null>(null)` — modal open when non-null; single source of truth for open/close
- `isFree = (event?.planTier ?? 'free') === 'free'` — defensive default to free if event not yet loaded
- Event Details hides premium modules entirely (no lock icon) on free events — reduces visual noise for non-organizers
- Participant badge visible at ≥15 (not always-on) — intentional design decision (human-approved)
- Checkout stub: any non-empty card fields trigger mock upgrade + synthetic txId — no Stripe, no validation
- `onTrialLimitReached` callback pattern — child component stays self-contained, parent owns PaywallModal state

**Issues Resolved:**

- `upgrade_required` 403 responses surfaced as PaywallModal instead of silent toasts / crashes
- PaywallModal call sites all correctly derive `isParticipant` from `useSession()` (was inconsistent before Phase 37)
- magic-link redemption cap case had no specific UX (generic error) — now shows "event is full" state
- `trial_limit_reached` on stale client state (e.g. category count drift) was silently swallowed — now opens PaywallModal

**Issues Deferred:**

- `UPGRADE_REQUEST_URL` placeholder — must replace Typeform slug before launch
- `/pricing` screen is a navigation orphan — not reachable from main nav; only via upgrade CTAs
- `plansApi.upgrade()` dead code — PATCH /api/events/:id/upgrade has no client caller in upgrade flow (checkout calls `eventsApi.upgradeEvent()` directly)
- Real Stripe billing integration deferred to v2.4 (BILLING-01, BILLING-02, BILLING-03)
- Photo gallery module (`photo_gallery`) deferred to v2.4 — `comingSoon: true` in MODULE_CATALOG

**Technical Debt Incurred:**

- `join.tsx` still missing `refreshEvents()` after invite accept (GAP-01 — carried from v2.2)
- `assetlinks.json` + `associatedDomains` placeholders — must replace before Universal/App Links work in production
