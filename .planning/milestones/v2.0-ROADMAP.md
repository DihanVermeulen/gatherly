# Milestone v2.0: Gift Exchange Platform

**Status:** ✅ SHIPPED 2026-02-22
**Phases:** 1–10
**Total Plans:** 27 (Phase 5 deferred; Phase 4-03 superseded by Phase 9)

## Overview

Transform Gatherly from a functional Secret Santa app into a mobile-first gift exchange platform where participants discover what people want and claim gifts anonymously. Starting with foundational database schema and privacy safeguards, we built wishlist CRUD, anonymous claiming with race condition protection, invite sharing with QR codes, JWT authentication with zero trust routing, offline-first sync via TanStack Query, magic link participant access, and inline assignment reveal replacing the decipher code mechanic. Phase 5 (iOS-style Mobile UI Redesign) was deprioritized and deferred to v2.1.

## Milestone Summary

**Phases Deferred:**

- Phase 5: Mobile UI Redesign (iOS-style Konsta UI, bottom navigation) — deprioritized; auth and sync features were higher priority. Deferred to v2.1.

**Plans Superseded:**

- Phase 4-03: Organizer invite management UI — replaced by Phase 9's magic link approach (participants join via emailed magic links with role-based access control; the manual invite list view wasn't needed)

**Key Decisions:**

- HS256 JWT with 15-min access tokens + 7-day HttpOnly refresh cookies — security/UX balance
- TanStack Query v5 as sole query library — eliminates react-query v3 conflicts and bundle bloat
- offlineFirst network mode — enables optimistic updates even when offline
- SELECT instead of DELETE for magic link redemption — tokens reusable within 7-day window (matches user mental model for emailed links)
- nanoid for invite codes — 21-char URL-safe vs 36-char UUIDs for cleaner URLs
- sort_order INTEGER DEFAULT 0 with composite index — efficient drag-to-reorder ordering query
- @dnd-kit with activationConstraint distance:8 — prevents tap/drag conflict on touch devices

**Issues Resolved:**

- Context overflow from QueryClient recreated on every render (fixed with module-scope QueryClient)
- Wishlist cache cleared on background refetch (fixed by merging cached wishlists in queryFn)
- Magic link single-use breaking re-click flows (fixed by SELECT-based redemption in Phase 10-02)
- Token expiry confusion (unified to 7-day window across magic_link_tokens and refresh_tokens)

**Issues Deferred:**

- Phase 5 Mobile UI Redesign — Konsta UI, iOS-style components, bottom navigation
- Phase 4-03 Organizer invite management UI — view/revoke invite list
- TECH-06 image compression (max 800px width, 80% quality) — planned for Phase 6 but DnD reordering was prioritized

**Technical Debt Incurred:**

- REQUIREMENTS.md traceability table not updated during Phase 7-10 additions (those phases added new requirements not reflected in v2.0 REQUIREMENTS.md)
- Invite management page (04-03) never built — organizers manage invites only from the event edit page's participants section
