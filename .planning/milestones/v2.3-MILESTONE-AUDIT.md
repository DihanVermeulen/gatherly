## Tech Debt by Phase

### Phase 35 — Paywall Components

**1. `UPGRADE_REQUEST_URL` placeholder (launch-blocking config)**
`constants/upgrades.ts` line 5: `"https://form.typeform.com/to/PLACEHOLDER"`
Every upgrade CTA opens a broken URL. Must replace with real form slug before release. Config value, not code gap.

**2. `plansApi.upgrade()` dead code**
`app/api/plans.ts` exports `plansApi.upgrade(eventId)` — never called. The in-app upgrade path is intentionally stubbed (external form CTA). Clean up when Stripe billing lands in v2.4.

**3. `/pricing` screen is a navigation orphan**
`app/pricing.tsx` is registered in the router stack but no in-app surface navigates to it. `PaywallBanner` CTA calls `WebBrowser.openBrowserAsync(UPGRADE_REQUEST_URL)` directly, bypassing the pricing comparison screen. Either wire navigation or document as deferred.

### Phase 36 — Paywall Wiring

**4. Participant badge threshold (accepted, not debt)**
`edit-event.tsx` shows "X/20" badge at `participants.length >= 15`, not from 0. Intentional design decision. Human-approved during Phase 36 verification.

**5. PREMIUM_MODULES client-only enforcement**
API `PREMIUM_MODULES = ["white_elephant"]` — only white_elephant is blocked at module-enable level. Polls, potluck, RSVP are enforced at usage level (trial limits), not at the enable-module API call. Intentional architecture per 34-01-SUMMARY.md. A direct API call could enable these modules on free events; enforcement happens when the user tries to create content.
