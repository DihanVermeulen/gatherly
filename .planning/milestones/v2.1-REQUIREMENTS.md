# Requirements: Gatherly v2.1

**Defined:** 2026-02-22
**Core Value:** Participants can easily discover what gifts people actually want and claim them anonymously, eliminating gift-giving guesswork while keeping the surprise element intact.

---

## v2.1 Requirements — Gatherly Mobile (React Native)

Port Gatherly to React Native (Expo + GlueStack) as the primary mobile client with full v2.0 feature parity plus organizer invite management.

### Navigation

- [x] **NAV-01**: App launches directly to Events screen (no marketing landing page)
- [x] **NAV-02**: App has persistent navigation (bottom tabs or equivalent) connecting main sections
- [x] **NAV-03**: Unauthenticated user is redirected to Login screen
- [x] **NAV-04**: Deep links from invite URLs open the Join Event screen

### Authentication

- [x] **AUTH-01**: User can log in with email and password
- [x] **AUTH-02**: User can register with name, email, and password
- [x] **AUTH-03**: Session persists via JWT auto-refresh (access token in-memory, refresh via HttpOnly cookie)
- [x] **AUTH-04**: User can log out and is returned to Login screen

### Events

- [x] **EVNT-01**: User can view a list of all their events showing name, status, participant count, and gift count
- [x] **EVNT-02**: User can create a new event with a name
- [x] **EVNT-03**: User can delete an event
- [x] **EVNT-04**: User can view event details including their secret assignment (inline reveal, no codes)
- [x] **EVNT-05**: User can add participants to an event by name
- [x] **EVNT-06**: User can remove participants from an event
- [x] **EVNT-07**: User can define couples who should not buy for each other
- [x] **EVNT-08**: User can set the number of gifts per person and generate secret assignments
- [x] **EVNT-09**: Organizer can view generated secret codes per participant

### Wishlists

- [x] **WISH-01**: User can view their own wishlist for an event
- [x] **WISH-02**: User can add a wishlist item with name, description, image, and priority
- [x] **WISH-03**: User can edit and delete their own wishlist items
- [x] **WISH-04**: User can browse all participants' wishlists in an event
- [x] **WISH-05**: User can claim a gift from another participant's wishlist (anonymous to wishlist owner)
- [x] **WISH-06**: User can unclaim a gift they previously claimed
- [x] **WISH-07**: Claimed status is hidden from the wishlist owner (privacy preserved)

### Invites

- [x] **INVT-01**: User can join an event via invite link (deep link opens Join Event screen)
- [x] **INVT-02**: Join flow handles all states: loading, event preview, join form, success, already joined, error
- [x] **INVT-03**: Organizer can view all sent invites for an event with their status
- [x] **INVT-04**: Organizer can resend a magic link invite to a participant
- [x] **INVT-05**: Organizer can revoke a pending invite

### Screen Templates

- [x] **TMPL-01**: Each screen is implemented to match its PNG template in `screen-templates/`
- [x] **TMPL-02**: If a screen template is missing, ask user to create it before implementing that screen
- [x] **TMPL-03**: All UI uses components from `components/ui/` (GlueStack); no custom UI primitives
